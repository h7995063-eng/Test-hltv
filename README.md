# HLTV Mini App — Документация API

Фронтенд приложения (Telegram Mini App) уже готов и работает.
Для полноценного запуска заказчику необходимо реализовать API на своем сервере.

В коде фронтенда (файл `app_v3.js`) есть константа `API_URL`.
Все запросы отправляются на этот адрес. Чтобы подключить реальный сервер, достаточно поменять значение `API_URL` на домен заказчика.

## Общие требования
- Формат данных: `application/json`
- Все ответы должны возвращать HTTP статус `200 OK` при успехе.
- CORS должен быть разрешен (если фронт и бэк на разных доменах).

---

## 1. Получение списка матчей
**GET** `{API_URL}/api/matches`

Этот эндпоинт вызывается при открытии вкладки «Матчи».

**Ожидаемый ответ (массив объектов):**
```json
[ { "id": 1, "map": "de_mirage", "team1": { "name": "FURIA", "score": 13, "players": [ {"nick": "FalleN", "kills": 28, "deaths": 10, "hs": 82} ] }, "team2": { "name": "MOUZ", "score": 9, "players": [ {"nick": "torzsi", "kills": 18, "deaths": 17, "hs": 70} ] } } ]
```

---

## 2. Отправка заявки на регистрацию команды
**POST** `{API_URL}/team-request`

**Тело запроса:**
```json
{ "name": "Team Name", "tag": "TAG", "logo": "url", "players": [ {"nick": "player1", "role": "Снайпер"} ] }
```

---

## 3. Отправка новости (Админка)
**POST** `{API_URL}/api/news`

**Тело запроса:**
```json
{ "action": "reject_news", "team": "FURIA", "text": "Текст" }
```

---

## 4. Одобрение новости (Админка)
**POST** `{API_URL}/` (корень)

**Тело запроса:**
```json
{ "action": "approve_news", "team": "FURIA", "text": "Текст", "photo": "url" }
```

## ⚠️ ВАЖНО: Демо-режим работы (localStorage)

На данный момент отправка заявок (Новости: смена состава и регистрация матча) и обработка их в админ-панели работают **локально в браузере** с использованием `localStorage`. 

Это сделано для того, чтобы можно было протестировать интерфейс без реального сервера. 
Когда вы (заказчик) реализуете API, вам нужно будет заменить в файле `app_v4.js` следующие функции:

1. **`submitRosterChange()`** (Смена состава) — вместо `localStorage.setItem` нужно отправлять POST-запрос на ваш сервер.
2. **`submitMatchRegistration()`** (Регистрация матча) — аналогично, отправка на сервер.
3. **`renderAdminRequests()`** — вместо чтения из `localStorage` нужно запрашивать список заявок с сервера (`GET /api/requests`).
4. **`approveRequest()`** и **`rejectRequest()`** — вместо изменения `localStorage` нужно отправлять POST-запросы на сервер для обновления статуса заявки и отправки уведомления в Telegram-бот.

### Предлагаемые эндпоинты для реализации:

**POST** `/api/roster-request` — принять заявку на смену состава.
**POST** `/api/match-request` — принять заявку на регистрацию матча.
**GET** `/api/requests` — получить список всех активных заявок (для админки).
**POST** `/api/request/approve` — одобрить заявку (и отправить уведомление игроку).
**POST** `/api/request/reject` — отклонить заявку (и отправить уведомление игроку).

*Уведомления игроку должны отправляться через Telegram-бота (используя `bot.sendMessage`), когда админ нажимает "Засчитано", "Состав изменён" или "Отклонено".*
